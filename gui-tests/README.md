# GUI-тесты: лабораторная работа №4, пункт 5

Тесты написаны на JavaScript для Playwright Test и выполняются в настоящем
Chromium против работающего сервиса. HTTP-ответы не подменяются. Каждый тест
использует отдельный браузерный контекст без авторизации. Новые пользователи
и бронирования не создаются.

## Сценарии

| Тест | Действия и проверки |
| --- | --- |
| GUI-01 | Открыть главную; проверить заголовок и гостевую навигацию; нажать «Войти»; проверить адрес, заголовок, поля и кнопку формы входа |
| GUI-02 | Открыть подготовленный календарь; выбрать следующий день относительно минимальной даты календаря; нажать «Показать время»; проверить HTTP 200, URL, сохранение даты после перехода и отображение результата |
| GUI-03 | Открыть регистрацию через навигацию; заполнить форму с некорректным email; нажать отправку; проверить фокус поля, ошибку HTML-валидации и отсутствие POST-запроса |

Отсутствие свободных слотов в корректно загруженном календаре допустимо.
GUI-02 проверяет результат в интерфейсе после отправки формы, а не только
заполнение поля. GUI-03 проверяет встроенную в браузер валидацию HTML, а не
серверную проверку email. Пароль в этом сценарии является тестовой строкой.

## Установка и запуск

На момент выполнения установлены Node.js 22.11.0, Playwright 1.65.1 и Chromium.
Фактическая версия браузера сохраняется в результатах. Браузеры находятся
в локальной папке `.browsers`, зависимости - в `node_modules`.

Из корня проекта, если сервис уже запущен:

```powershell
cd gui-tests
npm.cmd test
```

При необходимости сначала запустите приложение из корня репозитория:

```powershell
docker compose up --build -d
```

Тесты по умолчанию используют `http://localhost:8080` и календарь
`bf18fa0e-e219-48f4-b586-1cef9b3b5a6c`, подготовленный для лабораторной.
Для другого окружения задайте параметры перед запуском:

```powershell
$env:GUI_BASE_URL = "http://localhost:8080"
$env:GUI_CALENDAR_USER_ID = "ID-ПОЛЬЗОВАТЕЛЯ-С-НАСТРОЕННЫМ-РАСПИСАНИЕМ"
npm.cmd test
```

Запуск с видимым окном браузера:

```powershell
npm.cmd run test:headed
```

Тесты не используют фиксированных задержек: Playwright ожидает готовности
элементов и выполнения проверок. Один рабочий процесс, повторные попытки
отключены. Ошибка любого теста приводит к ненулевому коду завершения.

Для установки в новой копии проекта выполните в `gui-tests`:

```powershell
npm.cmd ci
npm.cmd run install:browser
```

`npm.cmd` используется для совместимости с PowerShell без изменения политики
выполнения скриптов. Глобальные настройки Node.js и браузеров не изменяются.

## Просмотр результатов

```powershell
npm.cmd run report
```

Откроется интерактивный HTML-отчёт со статусами, шагами, скриншотами и
трассировками. Сервер отчёта останавливается сочетанием Ctrl+C.

Файлы находятся в `../results/gui/`:

- `run-summary.txt` - текстовая сводка с версиями, статусами и длительностями;
- `playwright-report/index.html` - HTML-отчёт; просмотр через команду выше;
- `test-results/` - скриншоты и трассировки отдельных тестов;
- `results.json` - машиночитаемые результаты;
- `terminal-output.txt` - сохранённый вывод выполненного установочного запуска тестов;
- `report-overview.png` - готовый скриншот общего HTML-отчёта;
- `report-calendar-details.png` - готовый скриншот шагов GUI-02.

Последние два изображения можно обновить после запуска тестов командой:

```powershell
npm.cmd run report:screenshot
```

Повторный запуск тестов обновляет отчёт и папку `test-results`.
`terminal-output.txt` отдельно не обновляется обычным `npm test`.
